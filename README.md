# 王子姬 Prince Hime

> **當經典「電子雞」懷舊養成，遇上「QQ 彈彈史萊姆王族」、「動態性別轉化」與「宮廷線上多人決鬥」！**

《王子姬 Prince Hime》是一款基於 **Larch RPG 引擎** 開發的養成對戰遊戲。玩家在雲端培育所領養一顆半透明的「王室果凍晶凝蛋」，培育一隻 **QQ 彈彈（Squishy & Bouncy）的王室史萊姆**。透過日常餵食、清潔黃金便便、皇家特訓與心理輔導，動態決定其性別（英氣史萊姆王子 / 傲嬌史萊姆姬 / 琉璃真理君主）、外觀形態與戰鬥性格；當角色成年後，便可踏入線上大廳與全服玩家交流、進行 1v1 宮廷決鬥爭奪王位，甚至透過王室密令進行跨玩家「血統聯姻」。


---

## 🌟 核心特色

1. **QQ 彈彈的史萊姆王族（半透明果凍原質）**：
   - 告別生硬骨骼！以史萊姆天然的流體可塑性，完美支撐「性別外觀流動」：戳它泛起漣漪（Duang~）、走動噗啾彈跳、受擊壓扁回彈。頭頂微型小金冠隨著動作歡樂晃動！
2. **性別與外觀動態養成（流動性別機制）**：
   - 照顧方針、特訓項目（劍術 vs 禮儀）、餵食甜點或飲用三泉聖水，讓果凍原質分化為「英氣王子」或「華麗公主」，亦或解鎖特殊的「中性/雙面君主」。
2. **電子雞經典情懷重現**：
   - 餵食、生病照護、打掃「黃金便便」（可換取王室金幣！）。
   - 頭頂動態心情氣泡（`balloon`）與傲嬌文字吐槽（`bubble` 吐槽玩家）。
   - 放置過久負氣離家出走或變成流浪漢，需要發佈懸賞贖回。
3. **四維人格與戰鬥風格**：
   - **尊貴度 (Pride)**：影響護盾與暴擊。
   - **嬌貴度 (Spoiled)**：影響冷卻縮減與特殊道具加乘。
   - **武力/謀略 (Might / Wit)**：決定物理爆發或戰術計謀。
   - **社交魅力 (Charm)**：決定支援技能、外交成效與聯姻契合度。
4. **線上多人即時決鬥與社交**：
   - 單機專屬「皇家育嬰室」培育個人隱私（`soloMaps` 保護）。
   - 公共「王城中央廣場」即時看見其他玩家帶隊的王子/公主散步。
   - 支援 Larch 原生玩家對戰（`social.duel = true`），於萬國競技場一較高下。
   - 離線/跨服「王室婚約密碼（Gene Code）」，重現童年紅外線/密碼聯姻繁衍二代目。

## 序章（本機預覽）

    python3 scripts/gen_art.py            # 產序章美術到 art/raw/（已存在就跳過；art/raw 不進 git）
    python3 scripts/process_art.py        # 後製到 assets/art/：背景 1920×1080、國王與日誌去背、小人 116px（造型 224px 四列）
    python3 scripts/build.py              # 組出 dist/project.json（劇本寫在 build.py 裡）
    python3 ~/larch-preview/serve.py dist/project.json

標題畫面只有「進入王宮」：沒領養過就播序章，領養過直接進培育室（起點是「開機分流」卡，看 `intro_done`）。

**不用存檔**：寵物的狀態（含 `rpgState` 裡的名字與位置）都是跨週目變數（Larch「玩家變數 → 跨週目保留」，`build.py` 的 `PERSIST`），關掉再開就接著養。選單拿掉了存檔與讀檔，避免讀舊檔跟跨週目的值打架。王室日誌看狀態，也可以重看序章或重新領養（全部歸零）。跨週目的值存在玩家那台裝置（訪客）；登入帳號會不會跨裝置同步還沒驗證。

## 培育室的照顧循環

- 開著遊戲時每 30 秒餓一點（頭上冒飯碗）；點心籃餵食，玩具箱玩耍（加親密、也會餓）。
- 黃金便便：三個固定位置每 40 秒隨機冒一坨，走過去就撿起來換王室金幣。
- 離開多久：看不見的時鐘 HUD（`scripts/plugin/clock.html`，寫在 `settings.plugins.prince-hime.playback`，玩家不必安裝）每分鐘記下最後在場時間，讀檔時補上離線的飢餓與便便。反應分四段：1 小時內沒反應、1–8 小時「你回來了！」、8 小時–3 天鬧脾氣（餵了就和好）、3 天以上大鬧脾氣（先陪玩再餵）。從最後一次在場起算。

## 小王子／小公主分化

照顧的方式決定（規則在 docs/03 開頭〈分化（拍板版）〉）：玩具箱選「騎木馬比劍」傾向小王子、「辦小茶會」傾向小公主，親密度到 300 發光變身；日誌看得到目前傾向，260 時預告一次。分化後穿衣鏡的「平常」換成新樣子，聯動造型兩種共用。小人圖是 `gen_art.py` 的 `form-*`（小公主有粉色緞帶，用綠幕；洋紅幕會吃掉粉色），`process_art.py` 的 `FORM_PX` 是手量的身體寬。測試：`python3 scripts/build.py --grow=295`（開局親密度 295，玩一次就分化）。

## 競技場成年禮

分化後親密度到 400（`ADULT_AT`，約再陪玩 12 次），國王的使者送來邀請，任務提示帶到育嬰室門口（地圖最下面正中的地墊）；出發後是劇情卡：競技場 → 依分化走「比劍」或「茶會」→ 國王加冕 → 設 `adult` 回育嬰室。背景 `bg-arena`、CG `cg-adult-prince`／`cg-adult-hime`（`gen_art.py`，用分化後的小人圖當定錨）。日誌與門口在辦完後各換一句。測試：`python3 scripts/build.py --grow=395`（玩一次就分化並收到邀請）。

## 王城中央廣場（連線）

成年禮之後從育嬰室門口去，`art/objects_plaza.yaml` 設計、`python3 scripts/map_art.py gen|cut --map=plaza` 產圖（沒有舊整張圖：家具帶育嬰室整張當畫風、競技場背景當王國風格；地面照設計檔色塊配置圖生成，配置圖要先拉成生圖的 3:2，不然模型會自己重新排版）。**地面生成後要先跟設計檔疊圖比對**（草坪、步道、圓環的實際位置），物件照地面的實際位置對稱重排再切圖；先照設計檔擺、地面又沒照設計長，物件會像亂放（2026-10-09 作者指正）。合成預覽 `art/check/plaza-composed.jpg`。多人連線只開在廣場：`rpg-settings` 的 `online.soloMaps` 放育嬰室，對戰先關（寵物還沒有數值）。

## 作品聯動：禮物箱與穿衣鏡

- 原作品在「取得道具」卡打開 crossover，玩家在原作拿到過，本作的 `cross_<鍵>` 就是 `"true"`。目前接了 8 件：《仙泉．香布纏》的方天畫戟、環首刀、小木弓、鐵剪刀、冷梅帕；《咒泉．三結義》的雙股劍、青龍偃月刀、丈八蛇矛（清單在 `build.py` 的 `CROSS`）。
- 沙發上的禮物箱一次給一件，任務提示會帶路；領過的記在跨週目的 `got_<鍵>`。
- 貝殼鏡是穿衣鏡。五件收藏各解鎖一套造型：方天畫戟（呂布紅）、雙股劍（劉備白綠）、青龍偃月刀（關羽綠袍紅披風）、丈八蛇矛（張飛黑甲紅帶）、冷梅帕（貂蟬淡紫華服，手上拿帕子不拿兵器）。造型是「衣服＋手上的東西」的整套小人，一次穿一套，不分王子或姬。
- 造型＝資料庫裡另一個角色（`role:"npc"`；寫成 party 又沒 joinVariable 會被選單當成同行的隊友），用 hero 步驟換人，`outfit` 跨週目保留，進培育室時換回去。
- 選項卡的選項不能各自帶條件，所以穿衣鏡依「拿到哪幾件」的組合各一個分頁（5 件＝31 頁，事件分頁上限 98），選單只列拿到的。任務提示最多 16 條（超過播放器整個壞掉，`check_static` 會擋），「去穿衣鏡」只留一條，看 `mirror_new`。
- 造型小人：`gen_art.py` 的 `outfit-*`，參考《三結義》的兵器對照表與《香布纏》的戰甲定錨（劉備、關羽、張飛都是戰甲短甲；呂布有百花戰袍與黑金戰甲兩套，拿到方天畫戟兩套都進穿衣鏡（`build.py` 的 `OUTFITS` 第四欄是解鎖它的禮物）；劉備雙手各持一劍、劍直立在身體兩側（交叉的版本手握不好，作者要求不交叉）；貂蟬照華服定錨與冷梅帕道具定錨），從 `~/larch-taoyuan`、`~/xianquan-musou` 讀，不進本 repo。關羽身上有綠也有紅，關羽與劉備用藍幕。
- 造型小人的玉珮與面向：縮到地圖大小只認得出「奶白圓球＋大兵器」，所以每套腰帶正中垂掛一塊雕花玉珮，中間浮雕小小的姓氏（呂、劉、關、張、貂），下面垂流蘇（`gen_art.py` 的 `pendant-*`，拿作者認可過的原圖改一次；先試過胸前大字徽章，作者嫌廉價）。引擎只有一列圖時往反方向走會整張翻面，字會變鏡像，所以造型小人做成四列（下、左、右、上，引擎遇到四列就不翻面）：另一個方向用翻過的圖，再把玉珮圓盤（`process_art.py` 的 `BADGE`）貼回沒翻過的原樣。哪幾套原圖朝左記在 `ART_LEFT`。身體底部對齊離畫布底邊 7px（跟平常那隻一樣），比身體低的兵器尾端不算，不然那隻會浮起來。
- 小人的大小：引擎顯示寬度＝`sprite.scale` 格，跟圖幾 px 無關；1920 寬視窗一格約 80 螢幕 px。引擎不做平滑，圖要 1 px 對螢幕 1 px 才不糊，所以 `build.py` 的 `walk_sprite` 把 scale 設成「圖寬 ÷ 80」。平常那隻 116px、身體約 80px＝一格（2026-10-08 作者要縮回正常大小，原本身體約兩格、放大後糊）。造型兵器長短不一，整張塞進方框會讓身體忽大忽小，所以改成身體寬度跟平常那隻一樣（`BODY_PX` 是手量的校正表，重產哪張就重量哪張），畫布放大到裝得下最長的兵器（目前 224px）。黃金便便 64px、0.8 格。
- 走路動畫：資料庫角色的 `rig:"slime"` 只在戰鬥畫面作用，地圖上不會動。所以走路圖每列做 4 格果凍彈跳（原樣、壓扁、拉高往上跳、離地一點；`process_art.py` 的 `HOP`，用同一張圖縮放位移，沒有重新生圖），引擎移動時輪播、停下來看第 1 格（`build.py` 的 `FRAMES`）。
- 名字存在 `rpgState` 的 `@names`（依角色 id），選單「冒險者」照目前角色 id 查，查不到就顯示預設名「王子姬」。換造型就換了 id，所以時鐘 HUD 把名字抄到 `pet_name`（文字一律用 `{{pet_name}}`），也替每個造型角色 id 在 `@names` 填上同一個名字。
- 本機測不到真的收藏（要登入帳號），用 `--cross=lubu,guanyu` 假裝收藏裡有。

## 介面

- 介面 Skills 拿官方「小島日和」當底，顏色換成王子姬色系（`scripts/ui.py`，色表照 docs/05：燕麥奶白、蜜桃暖粉、蜂蜜奶黃、晨霧天藍，字用暖可可棕），換對話框、選項、選單、RPG 介面四塊；標題畫面沿用 `build.py` 的 `titleScreen`。版型與動態（果凍晃動的泡泡、彈出的名牌、圓形按鈕、手機造型的暫停選單）照原樣。
- 官方原始碼不進 repo：`ui.py` 第一次跑時從測試沙盒（作者在網頁套用過小島日和）讀到 `art/ui-ref/`（已 gitignore）。`python3 scripts/ui.py` 會檢查換色後的文字對比（規格書要求 4.5:1）。
- 地圖上的話一律用泡泡框（`say()` 預設 `presentation: bubble`、`who: hero`，冒在寵物頭上）；選項仍是下方選單。
- 造型角色的頭像用單格的 `slime-*-still.webp`：選單的立繪欄會把四列走路圖整張疊著畫。

## 分層育嬰室

照《仙泉．香布纏．續》嚴家的做法：純地面底圖＋每件家具一張自由圖片，寵物走到家具後面會被蓋住。地圖切成 48×36 細格（`TILE_PX` 40、寵物速度加倍，畫面大小與手感不變）。

1. 設計檔 `art/objects_nursery.yaml`：每件家具的佔地格（擋路）、往上的高度（可走進去被蓋住）、互動站點。北牆後面走不到，直接畫在底圖。
2. 色塊驗證 `python3 scripts/layout.py nursery`：檢查佔地重疊、出界、站點落在牆上，產色塊與設計圖 `art/check/blocks-nursery-plan.png`。
3. 產圖 `python3 scripts/map_art.py gen`：每件家具單獨綠幕／洋紅幕生成（植物有綠葉用洋紅），定錨是舊整張育嬰室的那一塊裁切；地面是同一張圖拿掉家具。
4. `python3 scripts/map_art.py cut`：去背、縮進圖框（每細格 40px，1:1 不糊）、下緣貼齊；地面 ECC 對齊原圖。東段欄杆是西段左右翻。
5. `build.py` 預設就是分層版（真圖產好就用真圖，沒有就用色塊）；`--old-map` 回到舊整張地圖。

測試與推送：

    python3 scripts/build.py --away=600           # 測試用：假裝上次離開 600 分鐘（直接跳培育室卡看反應）
