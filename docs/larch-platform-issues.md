# 給 Larch 官方的問題回報

做《王子姬 Prince Hime》時碰到的平台問題，一條一個錨點，可以直接貼連結（例如 `…/larch-platform-issues.md#p1`）。
每條都寫了怎麼重現、目前怎麼繞過、希望怎麼改。查證的前端版本是 2026-10-09 從 larch.ink 抓下來的那一份。

<a id="p1"></a>
## P1　網頁發佈沒辦法設定市集標籤

- 狀況：用網頁發佈（含更新版本），市集上的標籤只會有「視覺小說」。發佈視窗沒有標籤欄位，專案設定裡的「分類標籤」「遊戲類型」也不會帶過去。
- 查到的原因：前端發佈送出的內容固定是 `tags: ["視覺小說"]`，有參加創作者挑戰的再加挑戰名稱（`Marketplace-*.js`）。
- 影響：RPG、養成類作品在市集上也只顯示「視覺小說」，玩家用標籤搜不到。
- 當時的繞法（1.4，1.4.1 已改回泡泡）：沒有。agent 的 `larch_publish_game` 收得到 `tags`，但看前端程式，之後只要再用網頁發佈一次，標籤就會變回「視覺小說」。
- 希望：發佈視窗加標籤欄位，或沿用專案的「分類標籤／遊戲類型」；至少更新版本時不要蓋掉已經設好的標籤。
- 作品：<https://larch.ink/play/market/yaze/prince-hime>

<a id="p2"></a>
## P2　暫停選單「角色屬性」會列出所有數字變數，沒辦法藏

- 狀況：RPG 暫停選單的「角色屬性」會把專案裡每一個 number 變數都列出來（只排除 HP 變數）。內部計算用的數字也會給玩家看到，例如分化傾向、上次離開了幾分鐘。
- 查到的原因：前端是 `variables.filter(v => v.type === "number" && v.name !== hpVariable)`，沒有其他條件。
- 當時的繞法（1.4，1.4.1 已改回泡泡）：把這些變數宣告成 string、預設值寫 `"0"`。引擎比大小和加減時都會先轉成數字，所以邏輯照常運作，只是在變數面板上看起來型別不對。
- 希望：變數加一個「顯示在角色屬性」的開關。

<a id="p3"></a>
## P3　暫停選單的角色立繪會把整條行走圖畫出來

- 狀況：主角用單列、多格的行走圖（一張圖橫排四格動畫），暫停選單裡的立繪會把四格整條縮小排成一排，看起來像四隻並排。
- 當時的繞法（1.4，1.4.1 已改回泡泡）：另外做一張只有一格的靜止圖，給選單當立繪用。
- 希望：選單立繪自動只取第一格，跟地圖上播放動畫時的切法一樣。

<a id="p4"></a>
## P4　「單人地圖」會藏起其他玩家，但聊天還是跨地圖互通

- 狀況：多人連線把育嬰室設成單人地圖（`soloMaps`）。兩個玩家都在育嬰室時，畫面上互相看不到、角落顯示「單人遊玩」，但其中一人送出的聊天，另一人還是收得到。
- 重現：兩個瀏覽器設定檔、同一個作品，都停在單人地圖，其中一邊打字聊天。
- 不確定這是不是故意的設計（聊天以頻道為單位）。如果是，希望文件寫明；如果不是，希望單人地圖連聊天一起關掉，或給作者一個選項。

<a id="p5"></a>
## P5　一個事件超過步驟上限，整個遊戲打不開（官方 2026-10-10 已修）

- **官方回覆**：超過上限的事件現在只會停用那一個，其他照常跑，標題畫面進得去，並標出是哪張地圖、哪個事件 id；新增「批次重設變數」步驟（新增卡片 → 道具與數值），一步可設多個變數；每一段步驟上限 32 → 999、一個事件 160 → 9999。已用本機播放器快取確認上限字串是 999／9999。
- 以下是當初的回報內容：

- 狀況：RPG 地圖事件裡的一串步驟（例如選項裡某個答案底下的步驟）超過 32 個，播放器一開就顯示「這個畫面壞掉了」，訊息是「每一段步驟最多 32 個，一個事件最多 160 個」。壞掉的是整個遊戲，連標題畫面都進不去，玩家沒辦法繞過那個事件繼續玩。
- 重現：王子姬的「重新領養」選項要把每個存檔變數設回預設值，存檔變數多了兩個之後，那個選項底下的步驟從 32 個變成 34 個，本機預覽整個打不開（2026-10-10）。
- 說明：上限本身有寫在 RPG 規格裡，所以這條回報的重點是壞掉的範圍，跟上限多少無關。沒有測過這種地圖從 agent API 推上去時，伺服器會不會擋下；當時是在本機就發現，先修好才推。
- 當時的繞法（1.4，1.4.1 已改回泡泡）：拿掉兩個不需要還原的變數，build 腳本加檢查，超過 32 就停下來。
- 希望：只停用超過上限的那個事件，並在畫面或主控台指出是哪張地圖、哪個事件；或者讓「設回預設值」這種事有一個步驟可以一次處理多個變數。

<a id="p6"></a>
## P6　旁白的泡泡框掛在牆上的事件，超出畫面被切掉，看起來像卡住（官方 2026-10-29 已修：泡泡留在畫面裡，旁白也看 `who` 了）

- **官方回覆**（2026-10-29）：放在地圖最上面那排或畫面外的事件，旁白泡泡現在會留在畫面裡，也不會被左上角狀態列蓋住，「繼續探索」按得到。本機用 `index-0x5l8ou5.js` 確認過。泡泡仍掛在觸發的事件上（在牆那邊、不在主角頭上），已在同一張單追問「旁白泡泡要掛在主角身上的正確做法」。
- **官方第二次回覆**（2026-10-29）：旁白的 `dialogue` 步驟現在會看 `who`：寫 `"hero"`（或主角事件的 id）泡泡掛在主角頭上、不顯示名牌；寫其他事件的 id 就掛在那個事件上；沒寫維持掛在觸發的事件上。本機用 `index-D9xZRUbI.js` 確認過，王子姬 1.4.1 改回泡泡。
- 以下是當初的回報內容：

- 狀況：RPG 地圖上沒有說話者的旁白（`speaker: "narrator"`）用泡泡框顯示時，泡泡一律掛在觸發它的事件上。條件事件、自動事件通常放在玩家走不到的牆格，地圖最上面那一排的牆一放，泡泡就跑到畫面最上緣，大半截在畫面外，「繼續探索」的按鈕也幾乎看不到。這段時間主角不能動，左下方向鍵和任務提示也會收起來，玩家會以為遊戲當掉。
- 重現：在地圖第 1 列（牆）放一個條件事件，條件成立時跑一句 `dialogue`，`presentation: "bubble"`、`speaker: "narrator"`，進地圖就看得到。王子姬是成年後每天第一次進育嬰室的日常小事件；作者在專案模擬試玩時以為整個不能移動（2026-10-29）。
- 查到的原因：`rpg-engine-*.js` 裡決定泡泡位置的函式，`speaker` 是 `narrator` 時直接回 `{speaker:"", who:<觸發的事件 id>}`，沒有看步驟上寫的 `who`；`speaker` 是 `player` 時才掛在主角身上。王子姬原本每句都寫了 `who: "hero"`（主角事件的 id），以前旁白會掛在主角頭上，現在不會了。不確定 `who` 是不是官方支援的欄位，也可能本來就不打算讓旁白指定位置。查證的前端版本是 2026-10-29 從 larch.ink 抓下來的那一份（`index-ETRjpuQf.js`）。
- 當時的繞法（1.4，1.4.1 已改回泡泡）：放在牆上的事件，旁白改用畫面下方的文字框（`presentation: "text"`）；寵物自己說的話用 `speaker: "player"`，照樣掛在牠頭上。
- 希望：泡泡至少不要超出畫面（貼著畫面邊緣往內收）；另外，旁白能指定掛在誰身上，或在事件設定裡加一個「泡泡掛在主角身上」的選項。
- 已回報：2026-10-29 用 agent 回饋單送出（`fb-106e2f8b-a4a6-43f7-8d1b-3714db296960`）。
